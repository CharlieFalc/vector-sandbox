Pipeline stages & techniques
① Source
App / Service / SDK
Head Sampling
Probabilistic: record only N% of traces/events at creation time. SDK-level flag. Fast, zero network cost, loses tail context.
Client Filter
Drop low-cardinality noise, debug/health metrics, internal probes before emitting. SDK config.
Pre-aggregation
Convert raw events → counters/histograms locally (e.g. Prom client). Never send raw rows.
In-Memory Buffer
SDK holds metrics in a ring-buffer; exports on interval (scrape / push). Absorbs burst spikes.
SDK Rate Limit
Max events/sec or cardinality cap enforced in the SDK itself (e.g. OTEL View API).
→
② Agent / Sidecar
Per-node or per-pod collector
Batch Processor
Groups data points into fixed-size or time-window batches before forwarding. Reduces connection overhead dramatically.
Memory Queue Disk WAL
OTel Collector's persistent_queue writes to disk WAL. Survives agent restarts; decouples producer from downstream.
Metric Filter Label Drop
Drop entire metric families, strip high-cardinality labels (user IDs, UUIDs) before forwarding.
Rollup / Span Metrics
Reduce trace spans → RED metrics at agent level. One histogram instead of N span records.
Compression
Snappy / gzip on remote-write payload. Cuts bandwidth 5–10×.
Retry + Backoff
Exponential backoff + jitter when downstream is slow; respects 429/503 signals.
→
③ Gateway / Proxy
Central collector / remote-write proxy
Global Filter Routing Rules
Route metrics to different backends by namespace/team; drop org-wide noise centrally.
Fan-out Batching
Receive from N agents, re-batch for fewer, larger writes to ingestors.
Rate Limiting Token Bucket
Enforce per-tenant or per-service write quotas. Shed load before it hits storage.
Tail Sampling
See full trace before deciding to keep it (errors, slow spans). Memory-expensive but accurate. Lives here or in agent.
In-flight Buffer
Short-lived memory buffer absorbs micro-bursts between agent fan-in and ingestor writes.
→
④ Message Queue
Optional — high-volume / multi-consumer
Disk-backed Queue
Kafka topics absorb sustained bursts that outpace ingestor capacity. Replayable. Key pattern for >1M metrics/s.
Consumer Batching
Consumers batch-read N messages per poll cycle, write to storage in bulk.
Consumer Lag Alarm
Lag = back-pressure signal → trigger HPA on the consumer fleet.
Stream Filtering
Kafka Streams / Flink job does stateful aggregation and drops before ingestor sees it.
→
⑤ Ingestor / Writer
Cortex / Mimir / VictoriaMetrics write path
Write Batching
Accumulates samples in memory chunks; flushes to object store in large blocks. Amortises write cost.
WAL (Write-Ahead Log)
Durability guarantee without synchronous disk writes per sample. Ring-buffer on fast local SSD.
Back-pressure / 429
Ingestor returns HTTP 429 or applies admission control when chunk head series limit is hit. Gateway retries with backoff.
In-memory TSDB Chunk
Active series kept in RAM, compacted into immutable blocks. Limits random disk I/O.
Series Limit / OOO Drop
Hard cap on active series per tenant. Out-of-order samples optionally dropped or ingested with OOO window.
→
⑥ Storage
TSDB / Object Store / Columnar
Downsampling
Compact raw (15s) → 5m → 1h resolution automatically. Thanos / Cortex ruler runs this async. Query cost ↓ 100×.
Compaction
Merge overlapping blocks, rewrite with better encoding (Gorilla / delta-of-delta). Reduces storage 5–10×.
Retention Policy
Drop data older than N days at each resolution tier. Automatic TTL enforcement.
Block Compression
Parquet/Gorilla time-series encoding + Snappy/ZSTD. Columnar layout enables predicate pushdown.
Object Store Buffer
Ingestors stage blocks locally before uploading to S3/GCS. Decouples ingest rate from upload bandwidth.
→
⑦ Query Layer
Grafana / Querier / PromQL
Query Throttling
Limit concurrent queries per tenant, reject or queue excess. Prevents query storms from killing ingestors.
Results Cache Chunk Cache
Memcached/Redis caches aligned query results and raw chunks. Repeat dashboard loads hit cache, not storage.
Query Sharding
Split time-range queries into parallel shards across querier pods. Horizontal fan-out, then merge.
Auto Resolution Select
Querier auto-picks 5m or 1h downsampled data for long time ranges. Transparent to user.
Max Series / Bytes Limit
Kill queries that would scan >N series or >X GB. Protects shared infrastructure from runaway queries.
Cross-cutting — Infrastructure & Platform
HPA — Horizontal Pod Autoscaler
Scales collector, ingestor, querier pods based on CPU / custom metric (e.g. Kafka lag, active series). Prevents fixed-size fleet from being OOM-killed under burst.
VPA — Vertical Pod Autoscaler
Right-sizes memory requests on ingestors / agents. Avoids OOM kills from under-provisioned limits without over-allocating.
KEDA (Event-Driven Autoscaling)
Scales consumer pods directly off Kafka lag or Prometheus metric value. More precise than CPU-based HPA for async pipelines.
Pod Disruption Budgets
Prevent too many ingestor replicas being evicted simultaneously. Keeps WAL-backed state intact during node pressure.
Network Egress / QoS
tc-based bandwidth shaping on node level. Prevents a noisy-tenant Prometheus push from saturating the node's NIC and impacting other workloads.
Remote-Write Tuning
max_shards, queue_capacity, batch_send_deadline control Prometheus remote-write concurrency and back-pressure propagation back to the scrape loop.
